# 07 — User Experience (UX) & Design System

Dokumen ini mendokumentasikan arsitektur informasi, alur pengalaman pengguna (*user flow*), hirarki visual, dan sistem desain yang diimplementasikan pada antarmuka web dashboard di folder `static/`.

---

## 1. Konsep Desain: Neo-Brutalist "Takar Style"

Antarmuka dirancang dengan gaya **Neo-Brutalism** modern (*Takar Style*), yang menggabungkan:
- Garis batas hitam tebal dan kontras tinggi (`border-[3px] border-neo-black`).
- Bayangan keras tanpa blur (*hard drop-shadows*, misal: `shadow-neo` 3px 3px 0px #111111).
- Latar belakang kertas bertekstur hangat (*warm paper background* `#FFF9E5`).
- Aksen warna primer tegas: Kuning cerah (*Neo-Yellow* `#FFD21F`), Hijau daun (*Neo-Green* `#2E8B45`), dan Merah cabai (*Neo-Red* `#E52B2B`).

### Mengapa Gaya Ini Dipilih untuk UMKM?
1. **Kejelasan & Keterbacaan Instan:** Pelaku UMKM membutuhkan data yang mudah dipindai secara cepat tanpa dekorasi gradien yang membingungkan.
2. **Karakter Lokal & Tegas:** Visual neo-brutalis memberikan kesan alat kerja profesional yang kokoh (*utility tool*), bukan sekadar prototipe korporat generik.
3. **Efisiensi Performa:** Menggunakan CSS utilitas ringan (Tailwind CSS v3 via CDN) dan Chart.js tanpa overhead framework JavaScript yang berat.

## 4. Rincian Komponen Utama Dashboard

### 4.1 Pemilihan Topik / Produk (Topic Watchlist Tabs)
* Terletak di bagian paling atas konten utama.
* Menampilkan daftar pill bertema neo-brutalis untuk setiap produk yang dipantau (misal: `Cappuccino Cincau`, `Kopi Susu Gula Aren`, `Seblak`).
* Mengklik salah satu pill akan mengubah `state.activeTopicId`, menyegarkan seluruh visualisasi, metrik tren, dan feed ulasan secara sinkron tanpa reload halaman.

### 4.2 Ticker Live Pertambahan Views
* Elemen ticker monospaced di pojok kanan atas yang berkedip setiap ada event `trend_tick` dari SSE.
* Menampilkan pertambahan views riil (contoh: `+1.420 views sejak snapshot`). Memberikan keyakinan kepada pengguna bahwa data selalu diperbarui di latar belakang.

### 4.3 Panel Sintesis AI & Rekomendasi Inovasi
* Menampilkan kesimpulan pasar dalam bahasa Indonesia yang ringkas.
* Menyoroti 3 kotak berwarna terpisah:
  - **Kotak Hijau (Pujian):** Aspek yang disukai pembeli (misal: "Aroma kopi kuat", "Cincau kenyal").
  - **Kotak Merah (Keluhan):** Titik masalah produk (misal: "Terlalu manis", "Gelas plastik tipis mudah tumpah").
  - **Kotak Kuning (Ide Inovasi):** Rekomendasi konkret bagi UMKM (misal: "Sediakan varian less-sugar 50% dan kemasan cup lid sealer").

### 4.4 Indikator Visual Kata Kunci Terbanyak (Keyword Counter)
* Memenuhi **Requirement Wajib 2 Study Case 2**.
* Menampilkan daftar 10 kata yang paling sering muncul dari ulasan.
* Dilengkapi switcher tombol toggle:
  - `1 Kata (Unigram)`: Menampilkan kata dasar seperti `enak`, `manis`, `murah`, `lama`, `ramai`.
  - `2 Kata (Bigram)`: Menampilkan konteks frasa seperti `kurang manis`, `antre panjang`, `porsi banyak`.
* Bar horizontal proporsional menggambarkan perbandingan frekuensi relatif masing-masing kata.

### 4.5 Timeline / Feed Opini Publik
* Memenuhi **Requirement Wajib 1 Study Case 2**.
* Setiap kartu ulasan memuat:
  - Header: Ikon platform (Google Maps, TikTok, IG, Shopee), nama pengulas, timestamp relatif (contoh: `3 jam lalu`), dan bintang rating.
  - Teks Ulasan: Teks asli opini pelanggan.
  - Footer: Badge sentimen berwarna kontras (`POSITIF`, `NEGATIF`, `NETRAL`, atau `PENDING`) dan badge aspek (`#rasa`, `#harga`, `#pelayanan`).
* Dilengkapi kontrol filter dinamis untuk menyaring ulasan negatif saja (membantu UMKM fokus menyelesaikan komplain).

### 4.6 Pengukur Kuota & Anggaran (Usage Tracker Widget)
* Terletak di bagian bawah sidebar kiri.
* Menampilkan status kuota harian dan bulanan secara transparan:
  - YouTube Units: Pemakaian vs jatah harian (contoh: `1.200 / 10.000 unit`).
  - Google Maps Runs: Pemakaian vs kuota (contoh: `4 / 30 run`).
  - Social & Shopee Runs: Penggunaan actor Apify.
* Memberikan ketenangan pikiran kepada pengguna bahwa sistem tidak akan menimbulkan biaya tagihan tak terduga.

## 5. Manajemen Status Antarmuka (UI States)

### 5.1 Loading State
* Saat pengguna beralih topik atau memuat data baru:
  - Tombol aksi menampilkan teks proses (misal: `Menyiapkan…`, `Mendaftarkan…`).
  - Skeleton loading atau spinner SVG monospaced ditampilkan pada panel metrik dan feed.
  - Elemen UI tetap responsif dan tidak membekukan browser (*non-blocking asynchronous fetch*).

### 5.2 Empty State
* Jika suatu produk baru didaftarkan dan belum ada ulasan atau video:
  - Menampilkan kartu ilustratif neo-brutalis dengan teks informatif:
    *"Belum ada ulasan atau video yang memenuhi filter relevansi untuk produk ini."*
  - Menyertakan tombol saran: *"Coba tambahkan kata kunci sinonim atau perluas kota pencarian."*

### 5.3 Error State
* Jika panggilan API atau scraping pihak ketiga gagal:
  - Sistem menampilkan banner peringatan berwarna kuning/merah di atas dashboard.
  - Pesan error dijelaskan secara manusiawi tanpa kode teknis rumit (misal: *"Apify Google Maps belum dikonfigurasi. Tambahkan APIFY_TOKEN di file .env untuk mengambil data ulasan riil."*).
  - Toast notification muncul di pojok kanan bawah dan hilang otomatis setelah 4 detik.

### 5.4 Live State
* Status koneksi SSE ditampilkan melalui dot indikator di sidebar:
  - Hijau berkedip (*pulsing green*): Terhubung ke stream SSE (`LIVE WIB`).
  - Kuning/Merah: Koneksi terputus dan sedang mencoba rekoneksi otomatis (*auto-reconnecting*).

## 6. Desain Responsif & Mobile View

* **Desktop (>= 1024px):** Tata letak dua kolom penuh dengan sidebar kiri *sticky* (tetap diam saat konten kanan di-scroll).
* **Tablet (768px - 1023px):** Sidebar beralih ke bagian atas dengan navigasi horizontal bergulir (*horizontal scrollable source menu*).
* **Mobile (< 768px):**
  - Tata letak bertumpuk satu kolom (*single column flow*).
  - Tombol aksi pendaftaran produk diubah menjadi floating button atau form ringkas yang dapat diciutkan (*collapsible accordion*).
  - Tabel dan grafik chart menggunakan container dengan scroll horizontal untuk menjaga rasio visual tetap utuh.
